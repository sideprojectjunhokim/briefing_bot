## 이 제품이 실제로 뭔가 (문서보다 이게 우선이다)

**일하는 중에 한 시간마다 읽을거리를 하나 던져 주는 것.**
사용자 한 명(만든 사람 본인)이 쓴다. 발송은 없고 웹으로 보러 온다.

`docs/04-web-ux.md` 등 기존 문서는 **"매일 아침 08:00 하루 1회 브리핑"** 전제로
쓰여 있다. 이 전제는 폐기됐다. 문서를 읽되 이 차이를 항상 염두에 두고, 작업하며
문서도 같이 고쳐라.

## 왜 지금 구조로는 재미가 없나 — 이게 이번 작업의 출발점이다

하루 1회는 "밤사이 쌓인 것"이 있어서 성립한다. **한 시간에는 대개 새 게 없다.**
테크 뉴스가 시간당 5건씩 나오지 않는다. 그런데 지금 수집 프롬프트는 모듈마다
"상위 5~8개를 골라라"라고 지시한다. 시간당으로 돌리면 채울 게 없어서 잡글이 들어가고,
그 순간 신뢰가 먼저 죽는다. 12건짜리 목록을 시간마다 받으면 사흘이면 안 본다.

즉 **수집 주기만 바꾸면 실패한다.** 제품의 단위를 바꿔야 한다.

## 제안하는 재설계 — "한 시간에 한 장"

브리핑(모아 보여주기)에서 **배달**(골라 한 장 주기)로 뒤집는다.

- 한 시간에 **딱 한 편**. 3~5분이면 읽는 분량. 쉬는 시간 하나에 맞춘다.
- 봇의 일은 **모으기가 아니라 고르기**다. 12건 중 11건을 버리는 게 일이다.
- **줄 게 없으면 안 준다.** "이번 시간엔 없음"이 정상 상태다. 억지로 채우지 마라.
- 하루가 끝나면 실제로 읽은 대여섯 장이 쌓인다. 지금 서류철 은유가 그대로 맞는다 —
  스택이 "오늘 배달된 서류"가 된다.

이 방향이 좋은 이유: 시간당의 최대 적은 **양**이다. 양을 포기하면 골라 주는 일에
품이 들어가고, 그게 RSS 리더와 다른 유일한 지점이다.

### 같이 검토할 아이디어 (사용자와 정해라)

1. **이어 붙이기(threading)** — 읽은 것을 기억하고 새 항목을 거기 붙인다.
   "사흘 전에 본 React 컴파일러 이야기, 오늘 후속이 나왔다." RSS가 못 하는 일이고
   사람처럼 느껴지게 만드는 가장 싼 장치다. `read_at` 하나만 있으면 시작할 수 있다.
2. **읽는 시간 먼저 표시** — "3분". 쉬는 시간에 읽는 물건은 비용을 먼저 알려야 한다.
3. **빈 시간엔 아카이브에서** — 새 게 없으면 안 읽고 넘긴 예전 것 중 하나를 다시 꺼낸다.
   새것으로 위장하지 말고 "지난주 것"이라고 밝힌다.
4. **안 읽으면 눈치챈다** — 연속으로 건너뛰면 그 모듈을 줄이거나 대놓고 물어본다.
   설정 화면이 아니라 실제 행동에서 배운다.
5. **하루 끝 한 장** — 18시에 "오늘 읽은 것들의 흐름"을 한 문단으로.

전부 다 만들지 마라. **1번(이어 붙이기)과 2번(읽는 시간)이 값싸고 효과가 크다.**
나머지는 실제로 며칠 써 본 뒤에 판단한다.

## 인프라 — 시간당 실행이 제약을 바꾼다

**Supabase는 못 쓴다.** 무료 한도가 계정당 활성 2개인데 이미 다 썼다(CAS + 금은마켓).
새 프로젝트 생성이 막힌다. `supabase/` 아래 코드는 배포된 적도 실행된 적도 없다.

**Vercel Cron도 안 된다.** Hobby는 **하루 1회가 상한**이다(공식 문서 실측:
프로젝트당 cron 100개, 최소 주기 1일, 정확도 ±59분). 시간당은 Pro($20/월)부터다.

무료로 시간당이 되는 것 (실측):

| | 한도 | 비고 |
|---|---|---|
| **Cloudflare Workers Cron** | 계정당 트리거 5개, 10만 req/일 | 시간당 가능. 이미 R2를 쓰고 있음 |
| GitHub Actions | 비공개 저장소 월 2,000분 | 시간당이면 월 ~720분. 단 저장소 60일 무활동 시 스케줄 비활성화 |

**추천: Cloudflare Worker를 시계로만 쓴다.**

```
Cloudflare Worker (cron)  →  Vercel Route Handler  →  Neon 무료 Postgres
        시계만                   수집·선별·저장            저장
```

Worker는 매시 정각에 Vercel 엔드포인트를 때리기만 한다(`CRON_SECRET` 헤더).
수집 로직은 Next.js 저장소 안에 그대로 있어서 코드가 한 곳에 남고, 마이그레이션이
가장 얕다. Worker 코드는 20줄이면 된다.

**CAS 프로젝트에 스키마만 얹는 방법은 쓰지 마라.** CAS는 곧 결제와 출생 개인정보가
들어간다. 사이드 프로젝트 cron이 커넥션을 물면 그쪽이 멈춘다.

## 지금 코드 상태 (2026-07-28)

**되는 것** — 웹 UI 전체가 demo 데이터로 돈다(`web/lib/demo.ts`). 폴더 스택 →
탭 클릭 → 같은 페이지에서 문서 교체(하드 전환 없음) → ESC 복귀. 디자인 시스템
(`--ds-*` 토큰, Anton/Newsreader/JetBrains Mono, 종이+잉크 팔레트)이 온보딩부터
본편까지 일관되다.

**안 되는 것** — DB가 하나도 안 붙었다. 실데이터를 한 번도 본 적이 없다.
수집 코드는 배포·실행된 적이 없다.

**최근에 고친 것과 그 이유** (같은 실수를 반복하지 마라):
- 탭 이동이 `/c/[key]`로 하드 전환이라 매번 끊겼다 → 한 페이지 안에서 문서만 교체,
  탭은 `layoutId`로 제자리에서 날아간다
- "12건 도착" 이라 써 놓고 화면엔 한 줄만 보였다 → 원인은 레이아웃이 아니라
  **프롬프트가 목록을 만들라고 지시**한 것. 모듈마다 리드 문단을 앞에 세웠다
  (`web/lib/briefing.ts`의 `parseLead`)
- 온보딩이 검은 배경 + 컬러 블러 구체였다(팔레트와 정반대) → 서류철 모티프 선화로 교체

## 품질 원칙

> **목록은 데이터고, 글이 상품이다.**
> 제목을 다시 나열하는 문장은 아무것도 안 한 것이다.

- 모듈마다 리드의 **성격이 달라야 한다.** 핫딜은 "지금 사도 되나",
  시세는 "왜 움직였나", 테크는 "내 코드가 어떻게 바뀌나", 커뮤니티는 "읽을 값어치가 있나".
  넷이 같은 톤으로 끝나면 사흘 만에 안 읽는다.
  (CAS에서 같은 실수를 했다 — 17장이 전부 같은 리듬으로 끝나서 장별 마무리 형식을
  한곳에 모아 강제했다. 흩어 놓으면 시간이 지나며 다시 수렴해도 아무도 눈치 못 챈다.)
- **없으면 없다고 쓴다.** 억지로 채우면 신뢰가 먼저 죽는다.
- **숫자는 코드가 만든다.** 시세는 이미 LLM 없이 조립한다(`market.ts`) — 환각 0, 비용 0.
  이 경계를 넘기지 마라.
- 모델은 지금 `claude-haiku-4-5` 1회 호출(`summarize.ts`). "고르기"가 일이 되면
  더 좋은 모델이 필요할 수 있다 — 비용을 실측하고 판단해라.

## 작업 순서 (제안)

1. **제품 단위부터 사용자와 확정** — "한 시간에 한 장"으로 갈지, 지금의 모듈별
   브리핑을 유지할지. 이게 나머지 전부를 결정한다.
2. 인프라 확정(위 표) → `docs/01-architecture.md`·`06-decisions.md` 갱신
3. DB 스키마 + **첫 수집 1회 수동 실행 → 실데이터를 눈으로 본다**
4. 실데이터로 선별·리드 품질 조정 ← 여기가 진짜 작업이다
5. cron 연결 → 다음 시간에 자동 실행 확인
6. 로그인 화면 정리 (`.login-card`가 아직 옛 다크 테마 값이다)

## 이 저장소에서 지킬 것

- 커밋 메시지 한국어. **AI 귀속 줄(Co-Authored-By 등) 금지.**
- 주석은 **"왜"만** 쓴다. 이 값이 왜 이 숫자인지, 왜 다른 방법을 안 썼는지.
- **같은 것을 두 곳에 복사하지 마라.** 이미 한 번 당했다 — 펼친 폴더와 `/c/[key]`가
  본문을 각자 그려서 `FileBody`로 합쳤다.
- **화면을 바꾸면 실제로 띄워 본다.** `cd web && npx next dev`
- **"완료" 전에 검증 명령을 돌리고 출력을 근거로 댄다.** 최소 `npx tsc --noEmit`.
- 애니메이션은 `motion/react`, `useReducedMotion` 반드시 존중.
- 새 npm 패키지는 묻고 추가한다.
