# 07. 빌드 프롬프트 — 애니메이션 온보딩 → 대시보드 (단계별)

> Claude(Artifact/Claude Code)에 그대로 붙여넣어 쓰는 빌드 지시문.
> 비주얼 북극성 = "Dawn Dispatch" 프로토타입(금 히어로·카드 스태거·스파크라인).
> 원칙: 한 번에 다 짓지 말고 **화면 하나씩, 승인받고 다음으로.**

---

## 붙여넣을 프롬프트

너는 감각적인 프로덕트 디자인 엔지니어다. 개인용 "오늘의 브리핑" 웹 앱을 **세련되고 절제된 애니메이션**과 함께 만든다. 한 번에 완성하지 말고 **화면 단위로 하나씩** 만들고, 각 단계 끝에서 내 확인을 받은 뒤 다음으로 넘어간다.

### 제품
매일 아침 내가 볼 것들을 한 화면에 요약하는 **독립 개인 앱**. (참고: 금은마켓 같은 특정 서비스와 **무관**하다. 금은 여러 관심사 탭 중 하나일 뿐, 특별 취급하지 않는다 — AI·테크·자동차·게임과 완전히 동등.) 분야: **AI · 테크 · 자동차 · 게임/취미 · 금 시세 …**(확장 가능). "오늘 무슨 일이 있었나"를 가볍게 스캔한다.

### 비주얼 방향 — 깔끔 · 친근 · 모던
- **온보딩이 첫인상이다. 무겁거나 어둡지 않게, 친근하고 세련되게.** 넉넉한 여백, 부드러운 라운드, 명료한 위계, 편안한 대비. UI/UX가 직관적이고 다정해야 한다.
- **색**: 밝고 깨끗한 그라운드 기본, 절제된 단일 액센트 하나. 분야별 시맨틱 hue는 칩·아이콘 등 작은 곳에만(분야마다 톤 하나씩). 크림+세리프+테라코타, 보라→파랑 그라디언트 히어로 같은 흔한 AI 룩은 피한다.
- **타입**: 한국어 시스템 산세리프 본문 + 숫자·시각은 tabular 모노. 웹폰트 CDN 링크 금지(사일런트 폴백). 필요하면 @font-face data URI.
- **모션**: 목적 있는 모션만, 부드럽고 짧게. 온보딩 스텝 전환, 카드 스태거 등장, 숫자 카운트업, 호버 마이크로. **카드/탭 안에서는 좀 더 놀아도 되지만(예: 스파크라인 드로잉), 온보딩과 전체 골격은 절제.** 과하면 AI 티가 난다. `prefers-reduced-motion` 반드시 존중.
- **테마**: 라이트/다크 둘 다 토큰 기반으로 동등 설계. 토글이 media query를 양방향으로 덮어쓴다.

### 기술
- Next.js App Router (기존 스캐폴딩 `web/`에 얹는다). 데이터는 Supabase `briefings` 테이블에서 anon read. 아직 백엔드가 비어 있으면 **목 데이터로 화면부터** 만들고, 나중에 실데이터로 교체 가능하게 분리한다.
- 서버 0개 제약: 관리할 인스턴스 없음. Supabase + Vercel 정적/ISR로만 동작.

### 만드는 순서 (각 단계 = 동작하는 화면 하나, 끝나면 멈추고 확인받기)

**1단계 — 애니메이션 온보딩 (여기부터 시작)**
첫 방문자용 3~4 스텝 시퀀스, 화려하지 않지만 세련되게:
1. 웰컴 — 로고/워드마크가 새벽 그라디언트와 함께 페이드인, "오늘의 브리핑" 등장.
2. 관심 분야 선택 — 분야 칩(금·AI·테크·자동차·게임…)을 탭해서 on/off. 선택이 시각적으로 반응.
3. 브리핑 시간 선택 — 매일 몇 시에 볼지(기본 08:00 KST).
4. 완료 — 선택 요약 → "대시보드로" CTA. 스텝 전환은 부드러운 슬라이드/페이드, 진행 인디케이터 포함.
선택값은 localStorage에 저장(추후 계정 붙으면 승격). 다음에 열면 온보딩 건너뛰고 대시보드로.

**2단계 — 대시보드 셸 + 마스트헤드**
날짜·라이브 시계·'브리핑 생성됨' 새벽 라인, 분야 필터 칩. 빈 카드 그리드(스켈레톤)까지.

**3단계 — 분야 카드(공통 컴포넌트)**
모든 분야가 **동등한** 카드 하나. 카드당 헤드라인 3~4개, 분야 hue 칩, 타임스탬프, 소스 수. 스태거 등장, 필터 칩과 연동(표시/숨김). 특정 분야를 히어로로 privilege 하지 않는다 — 순서는 온보딩에서 고른 관심사 순.

**4단계 — 데이터형 카드 변형**
시세처럼 숫자가 핵심인 분야는 같은 카드 틀에 **숫자 블록 + 스파크라인**을 얹은 변형으로. (금 시세가 예시일 뿐, 코인·지수 등 어느 분야든 재사용 가능한 변형이어야 한다.)

**5단계 — 마감**
반응형(모바일 우선), 접근성(포커스 링·reduced-motion·대비), 실데이터 연결 지점 정리.

### 진행 규칙
- 큰 결정(온보딩 스텝 구성·데이터 계약·테마 토큰)은 코드 전에 먼저 합의. 사소한 건 스스로 정하고 나중에 보고.
- 각 단계는 "이 화면 이렇게 나왔고, 다음은 X" 한 줄 보고로 끝낸다. 승인 전엔 다음 단계로 안 간다.
- 목 데이터와 실데이터 fetch를 한 곳(`lib/`)에서 갈아끼우게 분리한다.

지금 **1단계(애니메이션 온보딩)**부터 시작해라. 시작 전에, 온보딩 스텝 구성이나 화면 전환에서 방향을 바꿀 만한 미결 사항이 있으면 한 가지만 먼저 물어라.
