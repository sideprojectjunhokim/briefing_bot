# 04. 웹 UX — 안 읽은 큐

> **07-28 전면 개정.** 이 문서는 "매일 아침 08:00 하루 1회 브리핑" 전제로 쓰여 있었다. 그 전제는 폐기됐다.
> 지금 화면의 단위는 **"이번 시간의 브리핑"이 아니라 "안 읽은 것 N개"**다.

## 왜 정량을 버렸나

하루 1회는 "밤사이 쌓인 것"이 있어서 성립한다. **한 시간에는 대개 새 게 없다.** 그런데 시간당 N장으로 정하면 한가한 시간엔 채울 게 없어 잡글이 들어가고, 그 순간 신뢰가 먼저 죽는다. 반대로 바쁜 시간엔 N장이 답답하다. 어느 쪽으로 잡아도 틀린다.

그래서 **수집 주기와 읽기 단위를 분리했다.**

- **수집은 KST 9~17시 2시간마다(5회/일)** 돈다(C-25, 예전엔 매시). 그 시간에 새 게 없으면 아무것도 안 쌓인다. **그게 정상이다.**
- **읽기 단위는 "안 읽은 것" 전부**다. 쉬러 왔을 때 2개일 수도 7개일 수도 있다.
- 봇의 일은 시간 칸을 채우는 게 아니라 **큐를 좋게 유지하는 것**이다. 12건 중 11건을 버리는 게 일이다.

## 홈 `/` — 큐

```
┌──────────────────────────────────────────────────────────┐
│ UNREAD                                                    │
│ 준호 님, 안 읽은 것 4개.                                    │  ← 0개면 "다 읽었어요"
├──────────────────────────────────────────────────────────┤
│ [최근 테크 뉴스 8장 중 6장을 안 읽고 넘겼어요. 줄일까요?]     │  ← 조건 맞을 때만
│                            [줄이기] [그만 받기] [그대로]     │
├──────────────────────────────────────────────────────────┤
│        ┌─ TECH NEWS ─────────────────────────┐            │
│   ┌─ HOT DEALS ──────────────────────────┐   │            │  ← 겹쳐 쌓인 스택
│   ┌─ MARKET ─────────────────────────┐   │   │            │     = 그대로 큐
│   ┌─ COMMUNITY ──────────────────┐   │   │   │            │
│   │ 3분 · 1일 전 것        OPEN ↓ │   │   │   │            │
│   │ ↩ 사흘 전에 본 …, 후속이 나왔다 │   │   │   │            │
│   │ [클리앙] 홈서버 정리글          │   │   │   │            │
│   │ +1 MORE                       │   │   │   │            │
│   └───────────────────────────────┘   │   │   │            │
└──────────────────────────────────────────────────────────┘
```

- **스택이 곧 큐다.** 폴더 하나 = 안 읽은 장 하나. 읽으면 사라진다.
- **같은 모듈이 여러 장 쌓일 수 있다.** 모듈 4칸 고정이 아니라 시간 역순 N장이다.
- 앞(아래)에 얼굴을 드러낸 게 **가장 오래 기다린 장**이고, 뒤로 갈수록 최신이다. 오래 기다린 것부터 집게 된다.
- 카드 표면 순서: **읽는 시간 → 언제 것 → (있으면) 이어 붙이기 한 줄 → 첫 항목 → +N MORE**.
  읽는 시간이 맨 앞인 건 의도다. 쉬는 시간에 집는 물건은 비용을 먼저 알려야 한다.
- 되꺼낸 장은 `1일 전 것`처럼 **밝힌다.** 새것으로 위장하지 않는다.
- 큐가 비면 사과하거나 채우지 않는다: *"지금은 쌓인 게 없습니다. 9~17시 2시간마다 살펴보고, 건질 게 있을 때만 놓아둡니다."*

### 펼침
- 카드를 누르면 **그 자리에서** 문서로 바뀐다(하드 페이지 전환 없음). 탭은 `layoutId`로 제자리에서 날아간다.
- 여는 순간 읽음 처리된다. 되돌리는 버튼(**안 읽음으로**)이 같은 자리에 있다.
- 읽은 카드는 이번 화면에서는 흐려진 채 남는다 — 열자마자 발밑에서 사라지면 어디를 보고 있었는지 놓친다. 다음 방문에 큐에서 빠진다.

## 모듈 아카이브 `/c/[key]`

읽고 나면 큐에서 사라지지만 없어진 건 아니다. 되찾을 곳이 필요해서 만든 화면.
그 모듈의 최근 20장을 날짜·읽는 시간·`안 읽음` 배지와 함께 접었다 편다. 본문은 홈과 **같은 `FileBody`**를 쓴다 — 두 곳에 복사하면 한쪽만 고쳐지고 그때부터 서로 다른 화면이 된다.

## 사이드바

색인의 숫자는 **안 읽은 장 수**다. 이 화면에서 숫자는 언제나 "아직 남은 것"을 뜻한다.
(예전엔 "오늘 몇 건 왔나"였다. 같은 자리에 다른 뜻의 숫자를 두면 안 된다.)

## 진입 흐름

```
/onboarding ──(서류철 열기)──▶ /login ──(이름 + 비밀번호)──▶ /
```

- 미들웨어는 인증 안 된 페이지 요청을 **`/onboarding`으로** 보낸다. 로그인이 유일한 입구면 온보딩은 도달 불가가 된다.
- 이름은 인사말용이라 브라우저(localStorage)에만 남는다. 비밀번호는 서버가 확인해 httpOnly 쿠키를 준다.
- **온보딩은 자동 이동을 하지 않는다.** 예전엔 "이름이 이미 있으면 홈으로"가 있었는데, 이름은 있고 쿠키는 없는 상태에서 홈 ↔ 온보딩 무한 루프가 난다.

## 톤·스타일

종이 + 잉크 근단색에 블루 하나만 팝(`web/app/globals.css` 상단 `--ds-*`). 다크 배경 + 컬러 블러 구체 같은 기본값 디자인은 이미 한 번 걷어냈다 — 되돌리지 마라. 로그인 카드도 07-28에 같은 팔레트로 맞췄다(그 전엔 거기만 옛 다크 값이 남아 온보딩에서 넘어오면 다른 제품처럼 보였다).

리드 문단은 항목보다 크고 느슨하다(`.fp-lead`). "읽는 것"과 "훑는 것"이 눈으로 구분돼야 한다.
