# 05. 로드맵

> **07-28 재작성.** 예전 Phase 0~5는 Supabase + pg_cron + 아침 1회 전제로 짜여 있었다. 그 경로는 폐기됐다.

각 단계는 "끝나면 실제로 뭔가 동작하는" 단위다.

## 0. 계정·키 — **사용자 손이 필요한 유일한 구간** ⬅ 지금 여기

코드는 다 짜여 있다. 아래를 채우면 배포된다. 절차는 `SETUP.md`.

- [ ] **Neon** 가입(neon.tech, 개인 계정, 카드 불필요) → 프로젝트 생성 → connection string 확보
- [ ] **Anthropic** 개인용 API 키 발급 + 월 지출 한도 설정
- [ ] **Vercel** 프로젝트 생성, GitHub 연동, Root Directory = `web`
- [ ] Vercel env 4개: `DATABASE_URL` · `ANTHROPIC_API_KEY` · `CRON_SECRET` · `APP_PASSWORD`
- [ ] GitHub repo secrets 2개: `BASE_URL` · `CRON_SECRET`

**완료 기준:** 배포 URL이 열리고 로그인이 통과한다.

## 1. 스키마 + 첫 수집 (반나절)

- [ ] `cd web && npm run db:push` — `db/schema.sql` 적용
- [ ] `/api/collect?secret=…`를 **브라우저로 직접 호출**해 1회 수동 실행
- [ ] 응답 JSON으로 어느 모듈이 몇 건 건졌는지 확인
- [ ] **연속 2회 호출 시 두 번째는 `no_new`인지 확인** (중복제거 검증)
- [ ] 홈에 카드가 뜨고, 열면 큐에서 빠지는지 확인

**완료 기준:** 실데이터로 만든 장이 화면에 있고, 읽으면 사라진다.

## 2. 리드 품질 조정 ★진짜 작업

여기가 이 제품의 승부처다. 목록은 데이터고 글이 상품이다.

- [ ] 실제로 나온 리드 문단을 읽어 본다 — 제목을 다시 나열하고 있지 않은가
- [ ] 모듈별 톤이 실제로 다른가 (`LEAD_ASK` 넷을 나란히 놓고 비교)
- [ ] 건질 게 없을 때 `SKIP`이 나오는가, 아니면 억지로 채우는가
- [ ] `pick_max` 기본 8이 많은지 적은지
- [ ] Haiku 1회 호출 실비용 측정 → 상위 모델이 필요한지 판단 (06 문서 D-10)

## 3. 시계 연결

- [ ] GitHub Actions `collect` 워크플로를 수동 실행(`workflow_dispatch`)해 통과 확인
- [ ] 다음 정시(±20분)에 자동 실행됐는지 Actions 로그로 확인
- [ ] 18시대 실행에서 하루 끝 한 장이 만들어지는지 확인

**완료 기준:** 사람 개입 없이 큐가 채워진다.

## 4. 소스 확장 (모듈·소스 독립)

지금 실제로 붙어 있는 건 `technews/geeknews` 하나뿐이다. 나머지는 틀만 있고 `enabled:false`다.
소스는 **쉬운 것부터 하나씩 추가하고 실측한다**(C-10). 붙는 것만 유지, 막히면 `enabled=false`.

- [ ] `hotdeal`: 뽐뿌 RSS → 퀘이사존 → 루리웹핫딜
- [ ] `market`: Upbit ticker + 지수(D-3) — template 렌더 유지
- [ ] `community`: 클리앙 → 루리웹 → 보배드림 → (방어 강함) 에펨·더쿠
- [ ] `technews` 2번째 소스: Hacker News (Algolia API, 영문 → 한국어 요약)
